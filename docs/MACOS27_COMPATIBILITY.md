# macOS 27 导入与顶边冲突兼容候选

## 用户反馈与证据

用户安装 0.1.1（2026091501）后报告持续出现“未能加入项目”；拖文件经过菜单栏时系统进入 Mission Control，与搁板交互冲突。截图证明这两个实际体验问题。本机 `sw_vers` 为 macOS 27.0 / 26A428。

只读日志有拖放期间 public.file-url 数据请求，但没有足以证明失败唯一原因的记录。0.1.1 的模拟提供者测试不能代表真实 Finder 跨进程拖放通过。SDK 将旧 loadItem 接口标记为 macOS 27 deprecated，这是兼容检查线索，不是已证实的根因。

## 当前修订

- 面板改为 NSHostingView 子类处理原生 draggingEntered/performDragOperation；直接从该拖放的 NSPasteboard 读取 NSURL。SwiftUI 继续绘制卡片，不再负责收件转换。
- 状态栏与面板复用 `ShelfImport` 的原始文件引用读取与自身拖拽标记检查。只读取本次拖放，不读取系统通用剪贴板，不保存文件内容。
- 移除旧异步 NSItemProvider 收件、回调收集和超时代码。原始项目顺序、失败计数、partial 状态、容量和固定保护保持。
- 新增 Control–Option–空格全局快捷键，在当前鼠标所在显示器展开搁板。面板顶部距离该屏可用区域上边界至少 48 pt；拖住文件时不激活应用，以保留拖拽来源会话。再次按下收起。
- 使用系统单一快捷键注册，不监听任意按键；注册失败时在菜单/图标提示中明确显示不可用，普通菜单入口仍可用。真实注册与拖拽期间触发未经过 UI 验收。
- 保留菜单栏点击、悬停和拖入；不修改 Mission Control、热角或系统偏好。新入口让工作流无需经过顶边。
- 原生面板导入记录的诊断仅含 URL 数量、失败数量和是否接收，不包含路径、文件名或内容。

## 验证与边界

- `ShelfStoreSmoke` 通过。
- `ShelfRefinementSmoke` 改为原生私有测试 pasteboard：NSURL 文件与文件夹、中文空格特殊字符、原始顺序、混合不支持/非文件输入、空输入、自身标记、partial 下游状态、容量/固定/撤销、22 份测试源文件内容不变均通过。
- 定位测试覆盖两块包含负坐标的显示器与边角点，候选面板不越界且远离顶边。
- 私有测试 pasteboard 操作中系统输出 sandbox_extension_consume 提示，断言仍通过；这些测试不证明实际 Finder 提供的权限扩展或真实隐私授权已经通过。
- 没有启动/控制 UI、改变系统设置或向真实拖拽会话注入事件。真实 Finder 导入、快捷键注册/拖拽触发、跨应用拖出、深浅色与多屏行为均待用户验收。
- HCT-2026-09-08-01/02：本轮以真实用户失败纠正此前验收边界；原生读入测试保留失败与部分结果，验证只引用、顺序、容量、固定保护和源文件不变，不把自动测试通过等同于真实拖入修复。

## 人工验证顺序

1. 安装 0.1.2（2026091502）；先用 Finder 中的普通本地文件拖到面板，确认图一不再出现。
2. 从屏幕中部拖住文件，按 Control–Option–空格，保持鼠标按住，移入旁边新展开的搁板再松手；确认无需经过顶边。
3. 检查文件夹、多选、自身拖回、拖出至目标应用，以及快捷键再按一次收起。
4. 若导入仍失败，报告拖入来源应用，以及松手位置是菜单栏图标还是面板。本版本的计数诊断可进一步区分未读到 URL 与路径接收失败。
