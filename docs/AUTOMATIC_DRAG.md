# 拖动文件自动展开（0.1.4）

正式发布记录见 [v0.1.4 发布回执](RELEASE_v0.1.4.md)。下面保留逐次候选的验证记录。

## 用户决定

用户认为拖文件时再按快捷键过于复杂，明确要求拖文件时自动出现搁板。默认工作流改为：拖起文件 → 菜单栏图标下方出现搁板 → 移入松手。此前“不做全局自动唤出”的旧范围限制由本次明确要求替代；快捷键与菜单入口作为备用保留。

## 具体行为

- 观察鼠标左键按下/松开，不监听任意键盘输入。
- 鼠标按住期间每 60 ms 检查拖拽粘贴板类型和变更序号；松开后停止计时。普通空闲不轮询。
- 同时要求：本次按下之后拖拽粘贴板变更、声明文件 URL、没有本应用拖出标记、位移至少 8 pt、经过至少 120 ms。旧文件拖拽数据、普通点击、文字拖动不触发。
- 一次拖拽只展开一次；位置固定在菜单栏图标下方，与手动打开和备用快捷键共用定位，不追逐光标、不抢来源应用焦点。
- 在面板外松开后 150 ms 收起；延迟为原生 performDragOperation 留出时序空间。放入成功/部分失败/容量拒绝已经产生反馈时，不被全局松开回调抢先关闭。离开面板但仍拖住时保持窗口，方便再次移入。
- 取消后最晚在鼠标释放时收起；不额外监听其他应用的 Escape 键。已打开的手动面板不因新全局检测而跳位或被自动会话关闭。
- 菜单“拖动文件时自动展开”默认开启，可关闭并持久化。观察注册失败时显示“自动展开不可用（点击重试）”，不宣称功能已启用。

## 隐私与权限范围

全局检测只使用拖拽类型、所有者变更序号与当前鼠标状态，不读取通用剪贴板，不获取检测中拖拽文件的路径/内容，也不保存鼠标轨迹。只有实际放入搁板时才通过原生拖放 URL 接收引用。未修改 Mission Control 或其他系统设置。

依据 Apple 的 NSEvent 事件观察及 NSPasteboard.drag/changeCount API 文档实现。工具没有启动产品或驱动系统 UI，因此未验证当前 beta 上的真实事件投递，也没有测试权限弹窗；运行时观察是否成功和用户实际操作仍是独立验收层。

## 验证

在 `ShelfRefinementSmoke` 中加入自动展开状态机检查：无按下事件、旧文件粘贴板、新文本、自己的拖出、微小位移、防抖、首次文件拖拽、单会话只出现一次、重复松开、下一次拖拽。原生 NSURL 导入、失败分类、顺序、固定、容量、撤销及源文件不变测试保持。

`HCT-2026-09-08-01`：注册失败有可见不可用状态；新会话必须有新拖拽证据，旧数据不得变成正常文件拖拽。自动测试验证检测状态分支；未证明真实 OS 事件或 UI 生命周期验收完成。

## 用户验收

安装后直接在 Finder/桌面拖起普通文件，确认不按键也会在菜单栏图标下方出现搁板；移入松手后能加入，鼠标留在面板上也会约 0.35 秒后开始收起。再检查普通鼠标移动、框选文字和拖动窗口不会误开，取消/移出后松开会收起，成功反馈与替换撤销不会被抢先关闭。关闭菜单开关后应停止自动展开。

## 0.1.4 定位与收起修正

用户明确纠正：自动展开仍应位于菜单栏下方。自动入口和备用快捷键均已移除鼠标旁定位路径。代码检查发现悬停与完成反馈共用计时任务，进入面板会取消成功后的收起；现在分离为独立计时通道。成功放入后 0.35 秒开始收起，撤销完成和拖出完成也使用独立计时；新拖入/关闭会取消旧完成任务。部分失败、拒绝及替换撤销仍保留可操作反馈。

HCT-2026-09-08-01 回归：取消悬停任务不取消完成任务、新会话取消旧完成任务、连续完成仅执行最新任务，自动化检查通过。Debug 构建通过。真实系统拖拽和窗口遮挡体验待用户安装验收。
